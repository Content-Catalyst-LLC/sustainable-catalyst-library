# Source Transparency and User Trust Policies

Knowledge Library v5.56.0 separates two concepts that must not be conflated:

1. **Source-quality signals** are provenance-backed observations about a source or research object, such as metadata completeness, source identity resolution, original-language preservation, transformation lineage, methodology disclosure, citation traceability, versioning clarity, correction/retraction status, or corroboration/contradiction counts.
2. **User trust policies** are owner-scoped preferences that decide how a user, project, team, or institution wants to handle sources displaying particular signals.

A source-quality signal is not a credibility verdict, endorsement, evidence weight, truth probability, or automatic Platform Core promotion. A user trust policy does not rewrite source signals or source history and is not portable without its owner/context.

The Library intentionally does not calculate a universal aggregate quality score or system-default trusted/untrusted verdict. Policy evaluation returns a user-selected operational disposition such as `allow`, `include`, `exclude`, `flag`, `prioritize-review`, or `require-human-review` while preserving the descriptive signal layer unchanged.
