# Sustainable Catalyst Library v4.3.23-r1 — Installer Validation Repair

## Purpose

This repair addresses an installer validation failure in v4.3.23 that occurred on environments where PHP `ZipArchive` compressed the generated DOCX fixture below an arbitrary 5 KB threshold.

The runtime product version remains **4.3.23**. No WordPress runtime behavior, Research Document Builder feature, Citation Studio behavior, Publications presentation, or Research Library page structure is changed by r1.

## Root cause

The original v4.3.23 regression test asserted that the generated DOCX fixture had to be larger than 5,000 bytes. DOCX is a ZIP-based OOXML format; the compressed size can vary substantially depending on the ZIP implementation and compression behavior. On the reported macOS/PHP environment, `ZipArchive` produced a structurally valid DOCX of 3,706 bytes, causing a false-negative release failure.

## Repair

The byte-size threshold was removed. Validation now checks the actual document package:

- DOCX has a ZIP signature and is readable as ZIP.
- ZIP integrity passes with no corrupt member.
- Required OOXML parts are present and non-empty: `[Content_Types].xml`, `_rels/.rels`, `word/document.xml`, `word/styles.xml`, and `docProps/core.xml`.
- The main document content contains the expected fixture title and DOI.
- Content types declare the WordprocessingML main document type.
- package relationships include the office document relationship.
- generated byte counts match the actual written fixture files.
- the fixture reports whether PHP used `ZipArchive` or `PharData` for cross-environment diagnostics.
- PDF validation is structural rather than dependent on an arbitrary byte-size threshold.

## Interrupted-install recovery

The original installer had already copied v4.3.23 files into the local Git working tree before validation stopped. The r1 installer is designed for that mixed state. It:

1. detects and accepts an already-modified working tree;
2. creates a safety backup before changing anything;
3. replaces the working tree with the corrected v4.3.23 repository payload while preserving `.git`;
4. runs the r1 repair contract and the complete retained v4.3.23 validation stack;
5. commits the repaired v4.3.23 state; and
6. pushes the current branch when an `origin` remote is configured.

No rollback to v4.3.22.4 is required.

## Publications boundary

The v4.3.22.4 Publications all-fields stack remains unchanged:

- `data-sc-field-stack="v4.3.22.4"`
- `data-sc-field-stack-mode="all-fields"`

The Publications page body must not be replaced for this repair.
