# Release Notes — Energy Systems Intelligence v0.1.0

## Sustainable Energy Knowledge Foundation

This additive release establishes Energy Systems Intelligence inside Sustainable Catalyst Library while preserving Library v5.11.0 and Carbon & Nature Intelligence v0.5.0. The Python Library backend advances from v2.6.0 to v2.7.0.

### Added

- 75 governed sustainable-energy concepts.
- 63 typed, source-keyed, non-inferential relationships.
- Six knowledge domains covering sustainable development, system flows, renewable technologies, biological carbon/bioenergy, efficiency/economics, and sustainability metrics/impacts.
- Six source-provenance records grounded in the supplied module materials/readings.
- Nine module SDG mappings with no inferred value for the missing SDG 15 coverage score.
- Seven explicit cross-platform handoffs.
- Active semantic handoffs to Carbon & Nature `soil-organic-carbon` and `forest-woodland`.
- Planned-extension markers, rather than invented targets, for biochar, anaerobic digestion/digestate, biomass-to-oil, and CO2-to-energy.
- GET-only Library backend endpoints under `/v1/energy-systems`.
- GET-only WordPress REST facade under `/wp-json/sc-library/v1/energy-systems`.
- Public shortcode `[sc_energy_systems_intelligence]` with Knowledge Map, Concept Registry, Sources & Provenance, and Platform Handoffs views.
- Deterministic content fingerprint for the complete knowledge payload.

### Preserved boundaries

- Library application stays at 5.11.0.
- Carbon & Nature Intelligence stays at 0.5.0.
- No PostgreSQL migration.
- No new environment variable or secret.
- No source PDF redistribution.
- No current policy, price, grid, resource, reserve, or emissions value is inferred from historical material.
- 2020 conversion factors remain provenance-only and are not activated for calculations.
- No indicator calculation, scenario simulation, technology ranking, policy recommendation, or sustainability score.

### Validation

Release validation checks Python compilation, PHP syntax, JavaScript syntax, deterministic domain construction, required module concepts, source vintage, SDG handling, Carbon & Nature handoff boundaries, WordPress wiring, backend routes, and no-write/no-calculator guardrails.
